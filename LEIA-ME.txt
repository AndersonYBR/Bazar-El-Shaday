BAZAR EL SHADAY — App grátis com portão de segurança (passo a passo)

ARQUITETURA (tudo passa pelo "portão"):
  App (navegador) ──> Edge Function "api" ──> Banco Supabase
                        │  JWT verificado
                        │  rate limit 60 req/min/usuário
                        │  whitelist de comandos e campos
                        └  chave service_role SÓ existe aqui

1. BANCO + LOGIN (Supabase)
   a) Crie conta grátis em supabase.com e crie um projeto.
   b) SQL Editor: cole TODO o schema.sql e clique em Run.
   c) Authentication > Users > Add user: crie o login da loja (e-mail + senha).

2. RATE LIMIT (Upstash Redis — grátis)
   a) Crie conta grátis em console.upstash.com.
   b) Crie um Redis Database (qualquer região).
   c) Anote os dois valores da aba "REST URL": a URL e o TOKEN.

3. O PORTÃO (Edge Function "api")
   a) No Supabase: Edge Functions > New function.
   b) Nome: api
   c) Cole TODO o conteúdo de supabase/functions/api/index.ts no editor.
   d) Em "Secrets" (ou Environment variables, tipo Secret), adicione:
      - SUPABASE_SERVICE_ROLE_KEY  (Supabase > Settings > API — a chave service_role)
      - UPSTASH_REDIS_REST_URL     (passo 2c)
      - UPSTASH_REDIS_REST_TOKEN   (passo 2c)
   e) Deploy. IMPORTANTE: mantenha a verificação de JWT ligada (não use
      a opção --no-verify-jwt). Sem token válido a função nem roda.

4. APP
   No app.js, cole no topo: SUPABASE_URL e SUPABASE_ANON_KEY
   (Supabase > Settings > API > Project URL e a chave "anon public").
   A chave anon é pública por design — a proteção real está no portão
   (rate limit + whitelist + chave forte escondida) e no RLS do banco.

5. HOSPEDAGEM GRÁTIS (Cloudflare Pages)
   a) Suba a pasta bazar-app num repositório no GitHub.
   b) cloudflare.com > Workers & Pages > Create > Pages > conecte o repositório.
   c) Pronto: https://...pages.dev com HTTPS automático.
   (Alternativas: Netlify ou GitHub Pages, também grátis.)

SEGURANÇA ATIVA NESTA VERSÃO
   1. HTTPS automático no hosting
   2. JWT verificado ANTES de qualquer operação (login obrigatório)
   3. Rate limit: 60 requisições por minuto por usuário (429 além disso)
   4. Whitelist: só comandos list/add/del/venda; só 3 tabelas; só campos
      válidos; id sempre UUID; venda valida estoque antes de gravar
   5. service_role só existe dentro da função (Secret) — nunca no navegador
   6. RLS no banco continua ativo (2ª barreira)
   7. Senhas com hash (Supabase); escape anti-XSS no app; queries via lib oficial
   8. Backup diário automático (plano grátis do Supabase)

OBRIGATÓRIO PRA NÃO QUEBRAR
   - A função e o app precisam estar no MESMO projeto Supabase.
   - Se trocar a chave anon/service_role, atualize também nos Secrets.
   - Limite de req/min: const LIMITE_POR_MIN no topo do index.ts.
